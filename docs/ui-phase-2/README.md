# المرحلة 2 — الإدارة والموارد البشرية والطلاب

لقطات `before/` (main بعد دمج المرحلة 1) و`after/` (هذا الفرع)، بالخط الفعلي Tajawal، بأسماء `<الصفحة>-<العرض>-<المظهر>.jpg`
(desktop=1440، mobile=390). لقطات `after/` الإضافية: `student-form-error-*` (فشل التحقق مع صف تسجيل) و`permissions-form-desktop-dark.jpg`.

## إعادة التشغيل
1. بيئة تجريبية معزولة: `cp .env.example .env && php artisan key:generate && touch database/database.sqlite && php artisan migrate --force`
2. بيانات وحسابات: `php artisan db:seed --class=UiE2ESeeder --force` (موثقة في `database/seeders/UiE2ESeeder.php`؛ كلمة المرور `password`).
3. `npm run build && php artisan serve --port=8002` ثم `BASE=http://localhost:8002 OUT=docs/ui-phase-2/after node tests/e2e/ui-phase-2.mjs`
4. اختبارات PHP: `vendor/bin/pest tests/Feature/UiPhase2Test.php`

## جولة التصحيح (بعد المراجعة)
- **نموذج الموظف:** صفوف المؤهلات والتواصل والتنبيهات والملاحظات تُرسم من أجزاء `admin/hr/employees/rows/*` (الصفوف والقوالب من الجزء نفسه). بعد فشل التحقق تُستعاد من المُدخلات القديمة بمفاتيحها (حتى لو حُذفت كل الصفوف)، ولا تُقرأ قاعدة البيانات إلا عند أول فتح؛ عدّاد الإضافة `data-next-index` لا يصطدم بالمفاتيح؛ قيم القوائم و«رئيسي» و«إجازة» (بما فيها إلغاء التحديد) تُحفظ؛ الحقول المضافة تحمل `aria-label` من القالب، و`forms.js` يراقب الإضافات اللاحقة.
- **التايم شيت:** جدول HTML داخل القالب بدل iframe، ببيانات `TimesheetController::buildTimesheets` المشتركة مع الطباعة (النتائج نفسها؛ استعلامات الدوام والحضور والمناصب دفعة واحدة بدل استعلام لكل موظف: 9 استعلامات لـ12 موظفًا).
- لقطات: `before/hr_timesheets-*` (نسخة iframe السابقة) و`after/hr_timesheets-*` (الجدول الجديد). صور نموذج الموظف لم تتغير بصريًا فلم تُحدَّث.

## أنواع الاختبارات (الحقيقي مقابل المحاكاة)
- **حقيقية:** `UiPhase2Test` و`UiPhase2FixesTest` (طلبات HTTP فعلية على sqlite بالذاكرة، بيانات تُنشأ ثم تُقرأ من الصفحات)، و`tests/e2e/ui-phase-2.mjs` (Chromium فعلي على تطبيق يعمل وقاعدة تجريبية).
- **محاكاة (مسمّاة كذلك في السكربت):** «[سلوك JS بحقن is-invalid]» يعترض استجابة صفحة إنشاء الموظف ويحقن `is-invalid` في حقل تبويب غير نشط؛ هو اختبار لسلوك `forms.js` وليس للتحقق من الخادم، لأن قواعد الخادم الحالية تتحقق من حقول التبويب الأول فقط ولم نخترع قاعدة جديدة.

## ملاحظتان لاحظتهما في الجولة السابقة — عولجتا في PR مستقل (`claude/rowad-hr-fixes`)
- معنى `hr_work_schedules.day_of_week` المخزَّن هو **0=السبت ... 6=الجمعة** (نموذج الموظف والجدول الافتراضي في `Employee::booted` وتوثيق `docs/full.md`: الأحد–الخميس دوام والجمعة والسبت عطلة)؛ صُحّحت قراءة التايم شيت وبطاقة «مواعيد العمل اليوم» لتحويل تاريخ Carbon إلى هذا الفهرس (`WorkSchedule::indexForDate`). لم تُعدَّل أي بيانات مخزَّنة ولا توجد migrations.
- التنبيهات والملاحظات صارت إضافية فقط في نموذج الموظف: المحفوظة تُعرض للقراءة، والحقول للإضافات الجديدة، وأي `id` مُرسَل يُتحقق من انتمائه للموظف.

## قيود معروفة
- صفحتا `admin/students/statistics` (وأي استعلام `DATE_FORMAT`) تتطلبان MySQL؛ على sqlite المحلية تعطي 500 (قبل التعديل وبعده)، فلم أستطع فحصهما بصريًا.
- «المناصب الوظيفية والاحتياجات»: لا توجد وحدة/مسار للاحتياجات في المشروع، فطُبّق التوحيد على المناصب فقط.
- لم تُعدَّل: مصمم الشهادات، صفحات الطباعة/المعاينة/التحقق، وقوالب التايم شيت للطباعة.
