## الصفحات المنجزة (من المسارات والعروض الفعلية)
ترويسة/مسار/شارات مشتركة (`page-header`, `breadcrumb`, `status-badge`, `kpi`, `empty-row`, `filter-bar` بزر «تطبيق» ومسح صريح)، واحتفاظ الفلاتر بالترقيم، وتسمية أزرار الأيقونات، واتجاه الأرقام والأكواد، وتمرير أفقي محلي للجداول:
- **المشاريع:** projects (قائمة/نموذج/hub)، paths (قائمة/نموذج/شجرة)، project-activities، projects/tasks (قائمة/تقويم/تفاصيل/نموذج/إحصائيات)، event-cards، media-plans، movement-plans، monthly-reports (+قوالب)، project-docs (وثائق/قوالب)، events-calendar.
- **اللوجستيات:** purchase-requests (قائمة/إنشاء/تفاصيل/تسعير/مساعدة)، warehouses، warehouse-items (قائمة/نموذج/المحذوفة)، assets، approval-rules، settings، statistics.
- **التقنية:** issues (قائمة/نموذج/تفاصيل)، equipment (قائمة/نموذج/تفاصيل)، statistics، emails.
- **العلاج الفيزيائي:** patients (قائمة/نموذج/تفاصيل)، followups، transfers، rooms، statistics.
- خارج المرحلة عمدًا: قوالب الطباعة (`paths/print`, `monthly-reports/print`, `project-docs/documents/print`) وأجزاء `project-docs/partials` — لم تُعدَّل (طبقًا للتعليمات: لا تغيير في الطباعة).

## إصلاحات ربط (pre-existing على main، وجدها المسح الفعلي؛ في commit مستقل)
- `project-activities/{id}/edit` كانت تعطي 500 (اسم وسيط المسار) ← `->parameters(['project-activities' => 'activity'])`.
- المخازن: قائمة المخازن 500 (اسم مسار غير معرّف)، وعروض `warehouse-items` في مجلد خاطئ، ونموذج الحذف يرسل `DELETE` لمسار `POST`، وصفحة «المواد المحذوفة» بلا عرض وبلا علاقة `warehouse` ومسارها بلا `{warehouse}` ← أُصلحت وحُصرت بالمخزن.
- نماذج: بطاقة الفعالية كانت تعيد صفوف السجل المحذوفة بعد فشل التحقق ولا تهرّب `< & >` في القيم المُعادة؛ طلب الشراء كان يفقد البنود المُدخلة بعد فشل التحقق ← تُستعاد الآن (بعد حذف كل الصفوف لا تعود صفوف السجل). زر حذف الصف كان يحمل تسمية «رفض».
- أزرار إضافة/تعديل/حذف في قوائم المشاريع/المسارات/التقنية/المخازن/الأصول/قواعد الموافقة لم تكن مقيّدة بالصلاحية (الخادم كان يرفض بـ403) ← صارت مقيّدة بـ`@canPermission` مطابقة لصلاحيات المتحكم.

## إعادة التشغيل
1. `cp .env.example .env && php artisan key:generate && touch database/database.sqlite && php artisan migrate --force`
2. `php artisan db:seed --class=UiE2ESeeder --force && php artisan db:seed --class=UiE2EPhase3Seeder --force` (الحسابات والبيانات موثقة في رأس `UiE2EPhase3Seeder`؛ كلمة المرور `password`)
3. `npm run build && php artisan serve --port=8002` ثم `BASE=http://localhost:8002 OUT=docs/ui-phase-3/after node tests/e2e/ui-phase-3.mjs` (`ONLY=0,1,2,3,4,5,6` لاختيار الأقسام؛ 6 = نموذج طلب الشراء)
4. `vendor/bin/pest tests/Feature/UiPhase3Test.php`

## قيود معروفة (خارج نطاق هذه المرحلة، وُثّقت ولم تُغيَّر)
- `admin/projects/statistics` و`logistics/assets/{id}` (عرض `AssetController::show` غير موجود) يعطيان 500؛ الأولى تحتاج MySQL (`MONTH()`)، والثانية دالة غير منفَّذة في المتحكم. لا mysqld متاح هنا، فصفحات MySQL-only لم تُفحص بصريًا.
- كمية مادة المخزن: الخادم يتحقق `required|integer|min:0` في الإنشاء والتعديل، والحقل الآن `min=0 step=1` مع إرشاد؛ الكسور تُرفض عبر مسار النموذج الحالي مع بقاء القيمة المُدخلة والكمية المخزّنة (مُختبَر). لم يُفحص أي مسار استيراد ولم يُعمَّم عليه شيء، ولم يُغيَّر نوع العمود ولا القواعد.
- توقيع طلب الشراء (canvas) وملفات المرفقات لا يمكن استعادتها بعد فشل التحقق؛ يجب إعادة اختيار الملف/التوقيع.
- عمود الحالة في `warehouse-items` يعرض «نشط/غير نشط» فقط؛ قيم أخرى في قواعد البيانات القديمة تُعرض «غير نشط».
